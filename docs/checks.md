# Проверка лабораторной №7

24.11.2026. Windows, Python 3.12.14, SQLite 3.53.1, PostgreSQL 18.6,
psycopg2 2.9.13. Прошли 17 тестов, включая два на реальном PostgreSQL,
а также flake8 и compileall.

## Запуск команд

В новой базе SQLite после двух `add` команда `list` вывела:

~~~text
1 | Дюна | Романы
2 | Алгоритмы | IT
~~~

Команда `delete 1` вывела «Книга #1 удалена.». Повторный запуск
`list` показал только `2 | Алгоритмы | IT`.

В отдельной базе PostgreSQL команда `add` записала «Солярис» в категорию
«Фантастика». Выборка по категории вернула `1 | Солярис | Фантастика`.
После `delete 1` новая команда `list` вывела «Книги не найдены.».

## Кэш

В обоих запусках `cache-demo` по категории с одной книгой дал такой вывод:

~~~text
Запрос 1: записей=1, попаданий=0, промахов=1
Запрос 2: записей=1, попаданий=1, промахов=1
~~~

В тестах SQLite `set_trace_callback` фиксирует выполненные `SELECT`.
Повторный вызов с тем же фильтром пользуется кэшем. После записи или удаления
тесты проверяют новый `SELECT` и актуальный список книг.
